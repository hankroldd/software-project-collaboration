# 协作消息

已有消息、Issue 评论或任务字段满足要求时直接使用。短协作只写任务、事实/问题、请求动作和依据；下列扩展字段仅在跨会话、重派、契约变化或需要回执时填写。不要为每条消息创建文件。

## 发送内容

消息/评论 ID；回复哪条消息：
仓库/变更组；任务 ID；尝试 ID（适用时）：
发送者/职责；接收者/职责；需要知悉的受影响任务：
类型：question / finding / change / blocker / result / receipt / cancel-request。
依据的基线/候选、契约版本或共享状态 revision：

现在观察到什么（事实、推测与建议分开）：
影响哪些范围；哪些工作可继续：
希望接收者采取的动作；必要检查节点或时限：
可访问的主记录/产物/证据；未验证范围：
是否需要确认：无需 / 已收到 / 接受行动 / 结果采纳。

## 接收与处置（需要时填写在原任务/评论）

回应消息 ID；接收者；核实时刻：
核对的任务/尝试/版本与实际访问结果：
状态：已收到 / 已接受行动 / 需补上下文 / 拒绝本次请求 / 已采纳结果 / 已替代。
已采取或下一步动作；未解决问题：
写回哪个主记录及其 revision/提交；通知哪些受影响任务：

收到不等于批准或完成。重复消息先查原处置；版本过期先交对应负责人比对。有副作用的动作不能只凭相同/不同消息 ID 判定可否重做。
