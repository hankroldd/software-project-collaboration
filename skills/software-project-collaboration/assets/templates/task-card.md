# 任务卡

单人小改可只填目标、范围和验证。已有Issue/PR或等价任务记录时补字段并引用，不复制另一份总账。

## 目标与范围

任务ID、目标、需求/AC：
输入契约及版本、输出契约：
优先级、工程风险、必须满足的约束：
允许修改的路径；共享API/schema/迁移/生成文件的负责人：
依赖任务及必须先确认的条件：
已有授权来源与限制；不得把本卡当作新增权限：

## 执行身份与资源（并行、跨宿主或重派时填写）

当前执行者、协调者/集成人：
本次尝试ID（仅在可能重派时使用）、最近核实时间：
宿主/相关版本、实际加载的技能版本与工具限制：
仓库、分支、工作树、任务BASE；已有未提交改动及其负责人：
Git索引/提交的负责人；共同集成的目标：
服务/端口、测试数据、数据库/卷、构建/产物目录及清理范围：
是否可再派子任务、总并发与预算约束：
结果接收位置与适当的进度检查节点：
共享信息入口、相关主记录版本及维护者：
通信通道、接收方、需确认的关键事件；无法接收时的既有回报路径：

## 验证与交回

验证方法、真实依赖与mock范围：
候选HEAD，或明确未提交的文件/补丁与内容指纹：
实际命令/操作、环境、结果及可定位证据：
实施者状态：done / done-with-concerns / needs-context / blocked / cancelled。
未验证、原问题/拒收ID、未完成MUST及其影响：
仍在运行的进程/上游任务、已发生副作用和必要恢复动作：
集成结论由集成人填写；done不自动代表已通过整体验收或已发布。
关键结果的消息ID/链接、接收状态、接受结论及对应集成记录：

任务过期不自动转移写入权；接管时保留旧成果，确认原写入状态并记录新的尝试。
