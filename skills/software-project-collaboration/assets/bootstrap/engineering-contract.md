# 工程约定

## 已确认事实

技术栈和版本以 lockfile、实际镜像和命令为准；本文件不预先选择 React/Vue、数据库或容器数量。
Git 历史策略、子模块指针、CI 必需项、审批边界沿项目约定，不自动统一为 rebase 或 merge。

## 分级与证据

需求 MUST/SHOULD/COULD/DEFER；工程风险 R0–R3；缺陷 S0–S3。
已有等级继续沿用，说明映射。低风险少流程，高风险重证据，不把任务紧急当作降低验证标准。

## 一份事实入口

PROJECT 记目标；spec 记行为；代码记实现；verification 记执行观察；STATUS 记现在；ADR 记决策。
同一事实不要多份手工复制；根 README 只链接动态状态。

## 协作与授权

写任务先划文件所有权，独立工作树可用时采用；共享运行环境由一个人调度。
已授权范围持续推进；超出范围的改变先形成具体差异和影响，再按有效规则处理。
