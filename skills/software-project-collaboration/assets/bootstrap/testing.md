# 验证方式

## 从需求到证据

每个验收点关联一个适当层级的证据：静态/单元/契约/集成/真实浏览器/真实模型/目标环境。
同名通过数量不能替代行为覆盖；跳过、未发现测试、环境阻塞分别记录。

## 项目必需命令

确认 package scripts、测试配置、CI 后填写 .engineering/project.json。
每条命令记录 cwd、输入夹具、所需依赖、超时和合格判据；不用无效占位命令。

## 真实路径

选最关键的一条用户路径，覆盖成功、关键失败、刷新/重入和权限边界。
检查同一 HEAD 和运行产物；SSE 页面等业务元素就绪，不等待整个网络静默。

## 门禁有效性

核对收集数、实际执行数、skip、退出码、job needs 和构建产物。
按风险测试门禁是否真的能挡住一个已知失败；不为普通改动反复全量测试。
