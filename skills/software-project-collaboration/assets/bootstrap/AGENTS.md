# {{PROJECT_NAME}} 协作约定

## 工作目标

按当前用户请求和本项目已确认范围完成可验证结果。先读相关代码，再决定需要读哪些文档；小改动不要遍读全库。

## 工程入口

读 docs/PROJECT.md 了解目标，读 docs/STATUS.md 了解当前状态；涉及接口、数据、发布时再读相应契约。
可使用 software-project-collaboration，按任务风险加载模块。已有更具体目录规则时一并核实。

## 关键规则

- 保留已有用户改动；同一任务记录工作树、BASE、HEAD，测试与提交必须能对上。
- 最小完整改动覆盖调用方和失败状态；复用现有组件，不为单个需求增加另一套框架或服务。
- API、权限、迁移、模型质量按风险验证；mock、真实服务、目标设备的结果分别报告。
- 未执行写 NOT_RUN，缺条件写 BLOCKED；不靠跳过门禁、删测试或修改合同制造通过。
- 独立审查只读，保留原问题；换会话不能抹去拒收结论。
- 继续已授权的可逆工作；生产、破坏性操作和外部发送的权限以会话与项目有效规则为准。
- 仅使用合成/脱敏夹具；不输出密钥、完整业务材料或敏感请求日志。

## 完成说明

说清改动、实际验证、未验证及影响。同步相关 spec/STATUS，不把“代码完成”写成“目标环境已上线”。
项目必需检查命令在 .engineering/project.json 中登记；null 表示尚未确认，不能视为可跳过的通过项。
