# 技术栈适配提示

## 通用项目

先识别语言、框架、包管理器、锁文件、测试入口、运行服务、部署形式和已有规范。
优先沿用工作中的技术栈；缺失的架构事实先核代码和运行配置，不从README旧描述猜测。
脚手架用维护方官方模板并记录版本。没有必要不要增加微服务、队列、k8s、向量库或统一插件平台。

## Vue3 / Naive UI / FastAPI

前端复用主题 token、Layout、表单、按钮、弹窗/Drawer、错误/空态；检查当前 router、KeepAlive、组件名和菜单配置的实际关系。
API 客户端的响应拆包明确只在一个层；用真实契约形状做组件测试，再单独验证真实服务。
后端复用身份、权限、service、数据访问、配置和审计；先看现有约定，不强推新的目录架构。
鉴权校验调用者与对象归属，授权读取与写入不能只靠页面置灰。
异步成功→后续读取失败、切页→返回、刷新→恢复、取消/重试、长列表和嵌套滚动按场景验证。
类型、数据库事务/并发、上传文件、SSE各有边界，不用一个HTTP 200代表全部通过。

## Dify / Workflow / Agent

先核实际 tag/commit、Console/Service API、运行组件、模型、插件和部署方式，不能拿main证明稳定版。
Dify承担的定义、配置、执行与宿主承担的发现、授权、选择、展示分清；按现有约定复用，减少重复参数编辑器或门户。
内部 Console API 包在受限后端：固定上游和路由、服务端凭据、对象权限；不能做任意URL代理。
工具/知识配置成功与当次真实调用分别验证；索引完成与上传完成分别验证。
SSE的中间消息、canonical final、持久化、历史和文件统一核对，保留旧模式语义。
不把业务系统的 user 字段、模型自报ID或租户ID当终端用户权限认证。
撤权、停止、版本恢复与已发生副作用的边界如实说明。

## 私有化/离线一体机

记录CPU架构、GPU型号/驱动、模型量化与上下文、容器镜像摘要、插件二进制依赖、磁盘卷、离线依赖包。
amd64/aarch64 的原生依赖必须对应；不要复制一套 .venv 后改名冒充兼容。
使用最少现有运行组件，证明开机启动、日志轮转、配置保留、升级/备份/恢复和断网可用。
上下文长度、并发和KV精度由实测共同决定，不按显存大小直接许诺性能。
新模型/量化版本跑相同固定业务样本，区分速度、格式、工具成功和事实质量。

## 二次开发与跨仓

保留上游版本锁、补丁清单与退出/升级策略；先找扩展点再改核心。
父仓与子模块记录各自SHA、接口与发布组合；子仓成功不代表父仓指针更新。
Git历史、门禁、证据预算按目标项目定义；一仓要求rebase不意味着另一仓可rebase。
