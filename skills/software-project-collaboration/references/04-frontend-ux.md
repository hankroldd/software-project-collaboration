## 输入与基线

接收目标用户、任务、既有页面、设计组件、真实接口合同与验收条件。
先确认是修复既有页面、增加页面还是建设新产品；不要默认重做视觉体系。
读取相邻页面、公共壳层、路由、权限、数据请求和样式变量。
Vue + Naive UI 项目优先复用现有组件、表单规则和主题；其他技术栈沿用其既有体系。
不要在 Vue 产品里为单页引入 React 壳，也不要为简单页面再引入 UI 框架。
保存必要的改前截图与用户动作，记录页面、角色、主题、视口和实际运行版本。
仅文案或样式微调按 R0/R1 执行；跨路由状态或 API 变化通常为 R2；权限和数据行为按 R3 判定。

## 先画用户路径

写一条最小完整旅程：“从哪里进入 → 输入什么 → 点击什么 → 得到什么 → 下次如何找回”。
确认每个主按钮都有业务动作、完成条件和失败反馈；装饰性按钮不算功能。
把开始、加载、空数据、无搜索结果、无权限、失败、部分成功分别定义。
区别“第一次没有内容”与“查询失败”，不得都显示空白页面。
保留用户正在输入的内容；刷新、切页、关闭面板的丢失规则应显式说明。
删除、退役、停用、下架、撤权分别按产品合同显示，不以同一危险操作替代。
基于现有信息架构减少步骤，避免增加不必要的筛选、确认弹窗和说明面板。
关键业务确认可以保留；不要因实现方便把每次技术调用都变成用户审批。
同一用户动作需要前后端共同完成时，先贯通一个动作，再扩展同类入口。

## 异步状态与数据边界

为每个写操作填写下表，不用一个 `loading` 覆盖全部结局。

| 结局 | 页面必须如何处理 |
| --- | --- |
| 请求进行中 | 阻止冲突操作或排队；保留输入和明确状态 |
| 写入成功 | 用服务端确认值更新视图，解除进行中状态 |
| 写入失败且未生效 | 保留可重试输入，说明原因和下一步 |
| 写入成功、后续刷新失败 | 保留已成功事实，提示列表暂未刷新，不重复写入 |
| 超时、结果未知 | 查询操作状态或使用幂等重试，不能直接断言保存失败 |
| 用户取消/离开页面 | 按合同取消任务或仅断连，处理迟到响应 |
| 权限变化 | 停止无权操作，显示仍可查看的内容，避免无限轮询 |
| 并发版本冲突 | 保留用户输入，展示冲突或重新加载选项 |

给同一资源的并发请求确定响应次序规则，避免旧请求覆盖新选择。
取消请求、卸载组件和结束后台任务分别处理；不能看到 AbortError 就认定服务器没有写入。
请求结束时只清理属于该请求的状态，避免旧请求的 finally 清掉新请求的 loading。
优先用写接口返回的权威对象更新页面，避免写成功后再次读取成为唯一成功判据。
需要后续读取时，拆分提交状态和刷新状态，单独处理失败。
API 客户端只在明确的一层解包信封；读取真实 body 与拦截器返回类型后再写访问路径。
用真实响应形状建立测试替身，至少保留代码、消息、数据层级和错误字段。
不要把替身写成前端当前希望收到的形状，再据此宣称联调成功。

值的展示和校验必须有明确规则：

| 值 | 检查点 |
| --- | --- |
| `0` | 可能是合法数量、费用或阈值，不自动视为空 |
| `false` | 表示明确关闭，不自动改成默认开启 |
| 空字符串 | 确认是合法空值、清空操作还是未填写 |
| 空数组/对象 | 区分无选择、空结果和返回结构错误 |
| `null` | 按合同解释未知、未设置或清空 |
| 字段缺省 | 兼容旧数据或部分更新，不随意补造事实 |

## 布局、生命周期与文件

先确定页头、标签栏、侧栏、内容区、底栏及各自滚动容器的负责人。
内容区可收缩时检查 `min-width`、`min-height`、flex/grid 分配及 overflow 链。
避免页面自行减一组固定像素推算壳层高度；复用壳层已有的高度和滚动约定。
表格横向滚动、弹窗正文滚动、对话内部滚动分别验证，避免两层垂直滚动互相遮挡。
粘性按钮不得盖住内容、焦点或分页；长内容与短内容都检查。
回到页面时保留筛选、分页、展开和滚动位置，按业务需要刷新数据。
使用 KeepAlive 时检查缓存 include 与组件 name；路由名、组件名、cache key 不天然相同。
共用一个组件的多个路由要定义各自状态键；不要改名解决一页却破坏其他页面。
区分 mounted、activated、deactivated、unmounted；缓存停用时暂停轮询，激活时避免重复启动。
事件监听、定时器、图表、文件句柄、流式连接都要有与生命周期匹配的清理方式。
缓存只提升体验；重建页面后必须能从服务端或明确的持久层恢复必要状态。

对话与文件至少验证以下路径：

- 新会话、继续旧会话、只读历史和无权限访问各有正确入口。
- 流式执行、人工补充、部分输出后失败和取消能呈现真实状态。
- 刷新和切页后，任务、消息、执行记录和文件仍归属于正确会话。
- 文件卡片出现前确认登记与持久化状态；临时地址不可冒充稳定下载地址。
- 预览、下载、再次打开使用当前用户权限和可访问 origin，不泄露内部主机地址。
- 下载失败不显示“文件不存在”，除非后端已经确认；连接断开也不等于文件丢失。
- 浏览器存储满、旧缓存或缓存损坏时，主界面仍可操作并能回到权威数据。

## 清楚表达与可访问性

页面优先说明用户可以做什么、已经发生什么以及下一步；隐藏不影响决定的实现术语。
先删重复提示、副标题和解释卡片，再补真正缺少的必要信息。
不要删除帮助用户避免错误的限制、错误原因和状态说明来追求“极简”。
保持完整句子、具体动作和准确对象；避免空泛修饰词、营销渐变标题和假进度。
对真实耗时未知的操作给阶段或已完成数量，不编造百分比。

| 避免 | 按实际状态改写 |
| --- | --- |
| “AI 智能赋能，高效完成数据闭环” | “上传表格后，检查重复记录并导出结果。” |
| “系统异常，请稍后重试” | “配置已保存，但列表刷新失败。点击刷新查看。” |
| “深度思考中…” | “正在读取 3 个文件。”仅在确有该事实时显示 |
| “为您精心生成完美方案” | “已生成草稿，请核对金额和责任人。” |
| “任务已完成” | 说明完成的具体对象；仍有失败项就同时列出 |

沿用现有主题、字号、间距、圆角、按钮高度、悬浮与禁用状态。
普通文本和大文本按项目采用的无障碍标准分别检查对比度，不凭肉眼判断。
控件要有可读标签；错误关联到字段；状态不能只靠颜色区分。
键盘能进入、操作和离开弹窗；关闭后焦点回到合理触发点。
异步更新尽量保留控件身份，避免重建按钮导致焦点落到页面外层。
检查窄屏、长中文、长文件名、缩放及项目已有的浅/深色主题。

## 产物、验证与反例

交付页面实现、必要的状态表、关键改前改后截图和真实动作证据。
构建与类型检查只证明编译条件；页面渲染、点击及恢复行为需要浏览器验证。
使用语义定位和用户可见结果断言；样式字符串存在不代表用户可以点击或滚动。
对涉及的关键旅程，验证真实服务端至少一条成功及必要的拒绝/失败路径。
注明哪些是 mock 页面测试、哪些是真实联调、哪些是人工观感判断。
按风险补测试；纯文案或轻微样式变更不机械新增复制实现的测试。
复查共用组件的其他页面，避免修复一页后破坏所有使用方。
不要用“接口返回 200”“截图看着正常”或“几十项单测通过”替代整条用户旅程。
不要把开发者日志、审查清单和框架参数塞进普通业务页面。
