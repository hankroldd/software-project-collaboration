# 软件项目全栈协作

把用户目标推进到本次授权范围内的可验证结果。以仓库事实为准，完成最小但完整的改动，保留下一位协作者能接着工作的证据。

核心是Markdown；可选辅助脚本需Python 3.10+，仓库快照另需Git。宿主的权限、hooks和会话不自动互通。

## 先做四件事

1. 读当前请求、有效的仓库/目录指令与相关状态页。保留本会话已有授权和用户纠正，不因模板重新索要确认。不要为小改动遍读全部文档。
2. 确认任务类型、目标仓库/工作树、基线与当前提交、已有改动、运行环境。分清研究、只读审查、实现、验收、发布；看代码的授权不等于发布授权。
3. 用一两句话确定本次结果和验收方法。含义清楚、实现可逆时自主选择；只有缺少会改变产品行为或权限边界的必要信息时提问，同时继续无阻塞工作。
4. 确认本任务由哪个工作流主持。用户或项目已选择 OpenSpec、Spec Kit、Superpowers 等时沿用其规格、账本和有效门禁，本套只补相关检查；否则由本套按风险路由，不创建第二套总账。

遇到多个技能、宿主或项目规则冲突，读取 [工作流治理](references/workflow-governance.md)。规则优先级由实际宿主和当前指令决定，本技能不声明高于其他来源。安装了某个技能不等于授权它接管任务。

## 分清三个维度

| 维度 | 取值 | 作用 |
| --- | --- | --- |
| 需求优先级 | MUST / SHOULD / COULD / DEFER | 决定本期先做什么；依据业务价值、约束、依赖与效果 |
| 工程风险 | R0 / R1 / R2 / R3 | 决定设计与证据；看边界、影响面和可逆性，不看代码行数 |
| 缺陷严重度 | S0 / S1 / S2 / S3 | 决定缺陷处置；看真实影响，不把所有建议写成阻断 |

若项目已有 L1/L2/L3、P0/P1 等定义，先记录映射，执行项目定义。不要把本套 R3 与别人的 P0 自动等同。

| 风险 | 典型任务 | 最小充分流程 |
| --- | --- | --- |
| R0 | 不改业务含义的文字、注释、局部样式 | 相关上下文→修改→内容/显示核对；不新建 spec、测试框架或多代理审查 |
| R1 | 单模块、影响可控、容易回退的行为修改 | 验收点→最小完整实现→针对行为的必要检查；只给值得保留的行为新增测试 |
| R2 | 前后端联动、文件/历史/异步状态、共享接口 | 短 spec/契约→纵向实现→受影响层测试与关键用户路径→证据和状态同步 |
| R3 | 权限/租户/删除、并发写、迁移、真实发布恢复、模型事实质量 | 边界和失败语义→负向及真实依赖验证→所需独立审查→发布/回退或业务验收证据 |

授权与工程风险分别判断：R3 不代表反复请示；现有授权覆盖时继续。目标环境不可访问时交付已验证结果并明确未验部分。金额、事实或权限含义改变的文案也可能是 R3。

## 一直守住的执行原则

- **最小完整改动。** 覆盖真实调用方、状态、配置、测试和使用文档；不只减 diff，也不借修错增加另一套框架、门户、容器或版本引擎。
- **先确认边界再抽象。** 优先已有组件、接口、命令、锁和部署方式。新增依赖/服务说明现存问题、维护成本、撤回方法。单消费者通常不需要通用平台。
- **同一份事实。** spec 记录约定，代码实现行为，证据记录观察，STATUS 记录现在。四者相互引用，不把旧方案或归档规范当当前状态。
- **固定被测对象。** 记录任务 BASE、候选 HEAD、工作树、关键依赖及运行产物。提交后有改动就判断哪些证据失效；另一工作树或旧镜像的绿不算本次完成。
- **分层如实报告。** 静态审读、mock、组件、真实后端、真实浏览器、真实模型、目标设备是不同证据；不把一种改名为另一种。
- **定义负向行为。** 空值、0/false、越权、失败、取消、超时、重试、部分完成都要有明确状态。网络超时不等于服务端失败，停止请求成功不等于任务已停止。
- **不修改规则让自己通过。** 不放宽允许清单、删除失败测试、跳过必需 job 或改验收条件制造通过。确属工具误报时先证明并按项目规则处理。
- **审查可以零发现。** 问题要有位置、触发条件、影响、依据。不凑数量、不因风格偏好改正常代码。独立审查不继承实现者结论；复审保留原问题账本。
- **上下文可接续。** 换模型或会话不等于完成审查。交付代码身份、已做/未做、未闭合问题和下一步。不假设 Claude 钩子会在 Codex 生效。
- **写入责任明确。** 每个任务明确负责人、允许写入范围、集成人和共享资源；同一工作树默认同一时间只有一个写入者。明确不交叠文件的并行例外仍需指定 Git、生成文件与公共记录的唯一维护者。独立worktree不隔离端口、数据库、卷和外部副作用；接管前核对旧执行者和迟到结果。
- **消息与主记录各司其职。** 重要结果核实接收与接受状态，契约、决定和当前状态写回各自主记录。共享事实带来源、版本、维护者与核实时间；迟到消息、摘要或代理记忆不覆盖较新的有效记录。
- **控制证据体积。** 遵循项目限额。缺省仅留短摘要、退出码、必要失败原文和索引；大日志、模型输出、构建产物用适当产物存储和哈希引用，不污染源码仓。
- **保护真实数据。** 用合成/脱敏夹具，不把密钥、生产数据、完整请求正文写进文档、日志、提示词或报告。外部技能/脚本先审来源、版本、权限、网络和许可证。
- **验证充分就交付。** 每次新增检查要对应具体风险或必需门禁。不无限重复计数、截图、上传和无关全套；不把未知记作完成。

## 模板与工具

按需复制模板并填写；字段不适用时说明原因，不把占位符当证据。

- [模板索引与字段说明](references/templates-and-tools.md)：spec、任务、ADR、API、UI、审查、验收、发布、运维、AI、交接。
- [跨宿主适配](references/host-adapters.md)：Codex、Claude Code、OpenCode 的发现、调用与权限差异。
- [安装与发行](references/distribution.md)：成熟安装器、固定版本、更新卸载及离线导出；仅安装/发布技能时读取。
- [技术栈适配](references/stack-profiles.md)：Vue/Naive UI/FastAPI/Dify 与通用项目。
- [来源与采用边界](references/sources.md)：机制取舍；普通编码任务不自动联网更新社区规则。

需要时才用 Python 3.10+ 标准库脚本，先看 --help。以下工具不安装第三方依赖，不运行任意仓库命令或部署服务：

1. scripts/bootstrap_project.py --root PATH --name NAME --tier minimal：默认预览；明确初始化时加 --apply，只创建缺失文件。
2. scripts/repo_snapshot.py --repo PATH --days 7：只读 HEAD、工作区和近期提交索引；--base SHA 固定任务范围。索引不等于审查。
3. scripts/check_evidence.py --root PATH --file RELATIVE_JSON：核证据结构、覆盖、文件哈希、结论；--expected-head SHA 核候选。通过只表示结构成立。
4. scripts/export_skill.py --root PATH --target all：离线导出预览；--apply 才创建，相同内容幂等、冲突拒绝，不提供自动更新/卸载，不改权限或既有 AGENTS/CLAUDE。
5. scripts/inspect_installation.py --root PATH：只读比较指定项目中的同名副本与链接；不推断全局优先级或宿主实际加载结果。
6. scripts/prepare_repository.py --root PATH --repository OWNER/REPO：仅准备发行时使用；默认预览，--apply 创建可审查仓库候选，不建远端或发布。

## 交付终点

对照目标和授权范围说明：解决什么、改了哪里、实际验证什么、未验什么及其影响。要求部署的任务验到目标运行版本；只读审查给可执行结论即可。不要写好代码就提前结束，也不要因无权做最后一步而跳过前面的已授权工作。

业务方看到行为与结果，研发看到精确文件、版本、命令与证据。用完整中文，不用巨大流水账或“全面优化、深度赋能、已全部闭环”替代事实。
